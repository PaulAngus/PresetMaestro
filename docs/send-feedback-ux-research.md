# Send confirmations

Reviewed 2026-10-04.

[Fluent 2 toast guidance](https://fluent2.microsoft.design/components/web/react/core/toast/usage) supports brief confirmation feedback at a predictable location, a seven-second timeout for confirmations without actions, pausing on pointer hover, and preserving keyboard focus. [Windows InfoBar guidance](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/infobar) warns that inline notifications can substantially move other page content, and recommends other surfaces for transient feedback.

Preset Sender, Favorites, Preset Index and preset/scene navigation reached from Amps now share one confirmation near the top, centred just below navigation. It overlays the page rather than adding a row, so appearance, updating and expiry cannot move the search, toolbar or results. The existing success/warning colours and checkmark/exclamation mark are retained. A bounded text column wraps long names. New sends replace the previous message rather than stacking duplicates. The device action remains available through its existing keyboard and pointer interactions; the confirmation never takes focus.

The feedback has an accessible name containing the title and detail, an assertive automation live setting, and raises a name-change event for each send. This exposes feedback through Avalonia automation without focusing it. Platform screen-reader announcement behavior still depends on the reader; it was not manually verified with a screen reader.

Product choices: the user's requested position near the top uses a 360-pixel width and an eight-pixel gap below navigation. Centring it keeps the Favorites task buttons, index sync actions and details dismissal reachable at the supported widths. A temporary overlay can cover part of the search/content beneath it; it does not move those controls. This deliberately uses the top centre instead of Fluent's usual top-right/bottom-right examples, retaining one predictable position across pages. The existing `SENT` heading is retained for consistency, a deliberate deviation from Fluent's sentence-case recommendation. Existing warnings retain their eight-second duration; successful sends use seven seconds. Hover pauses expiry and leaving restarts the interval. Send confirmation reports that the MIDI command was sent, rather than claiming device read-back verification. Relevant messages remain in the MIDI log.

Regression checks exercise Favorites sending, preset and scene buttons, double-clicks in both index and amp-filtered results, failed sends, retained keyboard focus, unchanged page positions and hover/expiry behavior. Rendered results are inspected in light and dark themes at 1440×850 and 1000×850 alongside these checks.

The code review extends the existing warning feedback to favorite-storage and shutdown-save failures. The editor remains open with the draft and its Save action, or closing is cancelled so the user can retry. This uses the established eight-second warning overlay; it deliberately does not add a persistent inline error bar as suggested by [Fluent message-bar guidance](https://fluent2.microsoft.design/components/web/react/core/messagebar/usage), preserving the requested stable page layout and shared message treatment. A repeated attempt shows the warning again and diagnostics retain the exception. Preset-name storage failures use the existing persistent sync outcome instead. Failure-state renders were inspected in both themes at the favorite editor's existing 1320-pixel minimum and at 1440 pixels; opening that editor raises a 1000-pixel starting window to 1320. Regression tests verify that failed saving causes no additional movement or focus change.
