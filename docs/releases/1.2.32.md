# Preset Maestro 1.2.32 release candidate

This candidate adds active-device confirmation for preset entry, favorites and
Go to, including scenes. A send is confirmed only when the requested preset and,
for scene requests, the requested scene are read back. Wrong selections, missing
replies and a lost connection display errors. A scene snapshot checks the preset
before and after the scene query. The four-second deadline, cancellation of older
checks and no automatic navigation resend apply to every route.

The maintainer explicitly selected MIDIHelperLibrary 0.3.12 for this candidate
on 23 October 2026. Its exact bundled package bytes and source manifest are
adopted in a separate commit/workstream. The manifest describes a working-tree
library build; this is retained honestly and is a shared-MIDI provenance and
qualification preparation gap. Do not rebuild that package as another version
or silently substitute package bytes to bypass the gap. Other core consumers
require their own normal candidates and shared-platform verification.

Unrelated in-progress diagnostic instrumentation and private-method removals are
excluded. This branch retains the normal Windows self-contained, compressed,
ReadyToRun single-file publication and normal ZIP/notice packaging. No test-only
product flags, startup/storage overrides or alternate dependency hosts are used.

Hardware and native functional acceptance remain with the shared platform, on
the unchanged normally installed candidate with actual dependencies, package and
binary hashes, a live global reservation and paired host lease. Use separate
application-change and shared-midi-change scopes. Existing Windows native recipe
gaps, other-consumer preparation, genuine failure reproduction and normal Mac
build/sign/package work remain incomplete until their evidence exists. Never
manufacture a device failure or artificial configuration/environment for release
acceptance. No release qualification is implied by packaging or component tests.

Publication receipts, hashes and handoff files are generated beside the candidate
artifacts after publishing; they are not committed into their own source identity.
