# Device terminology

Reviewed 2026-10-07.

The app now calls a profile's assigned device a **device**, replacing the user-facing term **library**. Each profile selects one device at a time; several profiles can use the same device and share its saved presets, scenes, amps and MIDI mapping. Favorites and tags remain specific to each profile. A device's saved data remains available offline. Separate imported copies remain supported; this wording change does not impose a new one-to-one hardware identity rule.

Config uses **Device for this profile**, **Selected device: …**, **Select device** and **Manage devices…**. Management uses **Add device**, **Device name** and **Rename device**. Sync and comparison actions use **Sync device**, **Check device** and **Check device again**. When a message refers to the local snapshot or an update, it says **saved device data** or **Update device data**, distinguishing stored information from the connected hardware. The sync confirmation still explains that it replaces the saved copy. Renaming and deletion apply to PresetMaestro's saved device information, and deletion confirmation explains that hardware presets are unaffected.

[Fluent 2 content-design guidance](https://fluent2.microsoft.design/content-design) recommends plain language, concise actions, familiar terminology and sentence case. [Windows writing-style guidance](https://learn.microsoft.com/en-us/windows/apps/design/style/writing-style) recommends familiar language, clear next steps and concise messages. These recommendations are applied to the existing Avalonia controls, status messages, tooltips and accessible names. Calling the saved assignment a device is the user's product choice; Microsoft does not prescribe this domain term. No deliberate deviation from the cited wording guidance.

Storage paths, serialized fields, device identities and internal control names retain their existing formats so saved profiles, exports, imports and shared data remain compatible. Earlier UX research and technical design documents may retain the previous terminology when describing historical decisions or internal types; the README and current usage guide use the new labels.

Validation: 190 existing focused checks passed across assignment, shared mapping, rename, import/export, first-connection setup, sync outcomes, comparisons, firmware/capacity, Amps, profile scan feedback and header behavior. Four import checks were rerun successfully after updating their explanation assertion. Actual Skia renders of Config, device management, rename, import, first-connection choices, update decisions and connection status were inspected in light and dark themes at 1440×850 and supported 1000-pixel-wide windows, including 1000×640 status views and 650/480-pixel sync dialogs. Labels wrap cleanly, actions remain readable and accessible names use the same device terminology. Existing keyboard dismissal, focus return, preserved mapping drafts and shared-data safeguards pass.
