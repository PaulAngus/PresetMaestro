# Windows and macOS UX decisions

Reviewed 8 October 2026. This work keeps the existing Avalonia Fluent theme and layouts, while adapting OS-specific keyboard and font choices. Native Mac visual approval remains pending until the M2 is available.

## Primary guidance and implementation

- [Microsoft keyboard interaction guidance](https://learn.microsoft.com/en-us/windows/apps/develop/input/keyboard-interactions) calls for standard control behaviour, logical navigation and predictable focus. [Fluent 2 accessibility guidance](https://fluent2.microsoft.design/accessibility) emphasizes visible focus and returning focus after temporary UI closes. Existing dialog dismissal, native window decorations, control automation names and focus restoration are retained.
- [Apple's keyboard guidance](https://developer.apple.com/design/human-interface-guidelines/keyboards) recommends standard shortcuts so knowledge transfers between apps. The preset picker's Find command uses Avalonia's platform command modifier: Ctrl on Windows, Command on macOS. First/last-preset navigation uses the platform's document-navigation gestures. This also corrects the final-preset destination in a column-major grid with padding. Modified keys are excluded from the app's unmodified numeric-entry/send shortcuts, so a Command/Control shortcut cannot accidentally enter or send a preset.
- [Fluent 2 typography](https://fluent2.microsoft.design/typography) defines the Windows type ramp around Segoe UI Variable. [Apple's font guidance](https://developer.apple.com/documentation/technologyoverviews/fonts) favors system fonts and their language coverage. `AppFonts` retains existing Windows faces and selects Avalonia's default UI face plus Menlo for Mac diagnostics. No Windows or Apple font files are redistributed. Actual Mac rendering and font fallback still require inspection.
- [.NET's application-data mapping](https://learn.microsoft.com/en-us/dotnet/core/compatibility/core-libraries/8.0/getfolderpath-unix) places `ApplicationData` in the appropriate user folder on both platforms. The existing storage API already uses it: `%APPDATA%/PresetMaestro` on Windows, `~/Library/Application Support/PresetMaestro` on macOS. Profile names now use a common portable filename policy, and case-insensitive name collisions are rejected even on a case-sensitive Mac volume.

## Product choices and deliberate limits

The shared Fluent styling is a product choice, not a claim to reproduce AppKit controls. Native window chrome and Avalonia's native file pickers remain OS-owned. The app continues to use a saved Light/Dark preference. It remains a single-window MIDI controller that closes its device connections when the last window closes; persistent document-app/Dock reopening behaviour has not been added. Verify the default Mac menu and quit behaviour during native acceptance before changing that lifecycle.

The Mac bundle icon is a lossless container conversion of the shared brand icon at 16–256 pixels. The shared PNG source also supplies the in-app header. The current Mac asset needs a Retina visual check.

No new details panes or dismissal/task controls were introduced. The existing close-at-header, Escape and focus-return requirements remain applicable to future UI work. Keyboard tests exercise both Windows and Mac command configurations, actual selection/focus changes and suppression of modified preset commands. Windows renders are inspected in both themes and at supported narrow/normal sizes; a Windows headless render is not a substitute for Mac rendering or VoiceOver verification. See the [M2 acceptance checklist](windows-macos-development.md#m2-acceptance-checklist--pending).

## App icon framing — 15 October 2026

[Microsoft's app icon design guidance](https://learn.microsoft.com/en-us/windows/apps/design/iconography/app-icon-design) recommends using the available space and keeping the silhouette legible at small sizes. Its [icon construction guidance](https://learn.microsoft.com/en-us/windows/apps/design/iconography/app-icon-construction) recommends transparent backgrounds and multiple sizes, including 16, 24, 32, 48 and 256 pixels. [Fluent 2 iconography](https://fluent2.microsoft.design/iconography) distinguishes product launch icons from interface system icons; the existing branded pick remains the app's product icon.

The product choice is to tighten the pick's framing from approximately 80% to 95% of the canvas height, keeping its proportions and a small transparent edge for antialiasing. This retains the pick-and-dial identity rather than adopting Fluent system-icon artwork. The header retains its 24-pixel layout slot and now reads the PNG directly, avoiding a small ICO frame being enlarged. `scripts/Update-AppIcon.ps1` rebuilds all Windows scale-factor sizes from the shared PNG and then runs the existing lossless Mac-container conversion. This Windows asset-preparation script does not run during ordinary application builds. No interaction, focus, keyboard or label behavior changes.

The PNG was reframed with built-in ImageGen using the [recorded prompt](app-icon-prompt.txt). Verification: all 15 ICO frames decode with transparent corners; the five ICNS PNG payloads match their ICO counterparts exactly. Before/after previews were inspected at 16, 20, 24, 32, 48 and 64 pixels against light/dark backgrounds. Actual Avalonia/Skia app renders were inspected in Light and Dark at 1000 and 1360 pixels wide; both existing startup layout checks pass. The native Mac Dock/Finder appearance remains part of Mac acceptance. Review images are under `build_test/icon-fill/`.

A subsequent Windows taskbar screenshot matched the previous 24-pixel icon despite the distributed executable containing the updated artwork. `scripts/Refresh-AppIcon.ps1` now sends the documented [SHChangeNotify item-update notification](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shchangenotify) after replacement, and the machine-local distribution helper invokes it for each executable and the existing Start menu shortcut. This preserves Explorer and its open windows. The refresh was applied to the current 1.2.14 copies; a native launch from `C:\bin` confirmed that version and the enlarged header/title-bar artwork. Taskbar appearance is checked separately from executable icon extraction.

## Mac font layout corrections — 12 October 2026

The first native Arm64 regression run exposed two Windows-sized fields that were too small with the Mac build's default face. Preset Index now uses a 256-pixel minimum table width on macOS (Windows retains 224), allowing fewer, wider tables at the same window size. The scenes table's numeric Scene column is 48 pixels on macOS (Windows retains 44), so the heading fits its text and gutters without expanding beyond the matching row column. Both changes are compiled only under `MAESTRO_MACOS`; Windows layout code and dependencies retain their existing values.

[Fluent 2 layout](https://fluent2.microsoft.design/layout) supports rearranging content as available space changes, and [Windows content layout and spacing](https://learn.microsoft.com/en-us/windows/apps/design/basics/content-basics) recommends consistent gutters and readable hierarchy. The exact table minimum and four-pixel column increase are application choices, not documented Microsoft requirements. Ellipsis, full-name tooltips, accessible row identities, selection and keyboard navigation remain available for names that exceed a field. We deliberately allow different table density on the two operating systems rather than reducing Mac text size or distributing Windows fonts.

The library-update scrolling test previously assumed that three compact differences overflowed the dialog. Mac rendering showed that they fit completely. Its fixture now changes all eight scene names on one of the same three presets, creating real overflow independent of font metrics. Production dialog sizing is unchanged. This continues to exercise the fixed Back footer, Escape, focus restoration and accept/cancel behavior required by [Fluent 2 dialogs](https://fluent2.microsoft.design/components/web/react/core/dialog/usage), whose header/footer remain available while the body scrolls. The existing native nested confirmation is retained; this correction introduces no additional dialog.

The eight original targeted cases and two table-density regression cases pass on Apple Silicon. The density regression retains explicit Windows counts and separately checks Mac counts around its five-to-six-table resize boundary, without changing selection, focus or the stored items. Mac-local Skia/headless renders were inspected in Light and Dark at 1000 and 1360 pixels for presets, and 1000 and 1440 for scenes. Headings align with numeric rows, long sample preset names fit, complete tag pills and overflow counts remain readable, and the overflowing review retains its Back footer. The tests also cover scene columns at 1298/1320/1920 pixels, data retention through resizing, accessible full identities, dialog keyboard focus and no MIDI sends while browsing. Screenshots and TRX results are under `build_test/macos-layout-fix/`. Windows Release cross-compilation passes with zero warnings/errors; execution on Windows and native AppKit/VoiceOver acceptance are separate checks.

Final hardware-independent Mac Release suite: **828 passed, 7 Windows-file-lock tests skipped, 0 failed** (835 selected tests). Physical Hardware/Compatibility categories were excluded. Native CoreMIDI loading/enumeration passed. Both dependency graphs pass formatting, and the final Windows Release cross-build has zero warnings/errors. Final TRX: `build_test/macos-layout-fix/final/`. The layout corrections did not change signing; the subsequent [native signing correction](windows-macos-development.md#native-signing-correction--12-october-2026) resolves local packaging.
