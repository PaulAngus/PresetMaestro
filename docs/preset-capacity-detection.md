# Preset capacity discovery

New Axe-Fx III libraries use the automatically detected family. They do not ask for Original, Mark II or Turbo during connection or creation. Offline creation still needs a device family; FM9 and FM3 use their established 512-slot definitions. Legacy revision-specific libraries retain their existing data and limits.

At the first sync of an unresolved Axe-Fx III library, query zero-based slot 512 (the 513th location) with the read-only name command `0x0D`. A checksum-valid reply for model `0x10` and that exact address establishes 1024 slots for the supported 512/1024 range. Empty names are still valid evidence of an address. Wrong-model, wrapped-address, corrupt or missing replies do not establish capacity. The request uses the existing serialized MIDI gate, cancellation and late-response quarantine. No preset is selected by this probe.

The [official third-party MIDI guide](https://fractalaudio.com/downloads/misc/Axe-Fx%20III%20MIDI%20for%203rd%20Party%20Devices.pdf) documents the name query and echoed slot but does not specify invalid-slot behaviour. We therefore do not infer 512 from a timeout or invent a negative-response code. An uncertain result asks the user for 512 or 1024 slots during sync, with no default selection and a Cancel action. This is the deliberate fallback until an unambiguous invalid-slot response is verified on hardware. Production probing currently returns positive 1024 evidence or unknown; synthetic tests do not expand hardware validation.

`IndexDevice.PresetCapacity` persists the detected or confirmed capacity for the generic family. A successful scan start saves it together with the attempt before writing checkpoints, so failed/cancelled scans and Resume reuse the limit. Cancelling the capacity choice writes no scan or capacity. Unresolved automatic libraries cannot contain scans. Existing numeric enum values and legacy library definitions remain unchanged; the generic Axe-Fx family is appended to the enum. New automatic libraries require a version of the app supporting that variant.

All scan ranges, completeness checks, storage/checkpoint bounds, full match ranges, Amp catalogue completeness, decoder limits, progress, numeric sending and favorite preset selection use the saved library capacity. Family defaults still apply when no resolved matching library exists. The probe discovers capacity, not a hardware revision or physical-unit identity.

## UI guidance and product choices

[Fluent 2 progress guidance](https://fluent2.microsoft.design/components/web/react/core/progressbar/usage) calls for indeterminate progress when the amount of work is unknown, switching to determinate progress when it becomes known, and useful status text for failures. Discovery displays “Checking preset capacity…” with an indeterminate bar; the scan then shows its actual slot total. Existing Stop sync and connection dismissal remain available.

[Windows dialog guidance](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/dialogs-and-flyouts/dialogs) supports requesting information needed to continue, a concise instruction, explicit action labels and a safe dismissal action. The fallback offers a labelled capacity choice, Continue sync and Cancel. Continue is disabled until a selection is made. Keyboard focus starts in the choice; Escape/native close cancels, and focus returns to sync. Disconnect cancels the modal without saving a choice.

Product choices: detection runs only for a new unresolved Axe-Fx family library; saved capacities are reused. The bounded name probe uses the existing 1.5-second name-query duration. The confirmation uses the existing 420-pixel owned Avalonia window pattern, adapting WinUI guidance to the app's controls. It is nested above the sync window and does not dismiss on outside click. Light/dark renders at 1440 and 1000-pixel app widths, with 650/480-pixel sync windows, were inspected for readable wrapping, hierarchy and reachable actions.

Regression coverage includes exact-address correlation, wrong-model/wrapped/corrupt replies, empty valid replies, timeout uncertainty, cancellation, known-family no-op probing, 512/1024 persistence and scan ranges, repeated sync without reprobe, send bounds, partial-scan resume, unchanged data on dialog cancellation, and disconnect during confirmation. No Axe-Fx III hardware was available for this change's boundary validation.
